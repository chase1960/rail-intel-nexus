# 记忆与自进化 · MEMORY

情报系统的难点不在"今天抓到什么"，而在**"上周的判断，这周还算数吗"**。记忆就是把这个问题的答案存下来。

## 1. 三层结构

| 层 | 内容 | 生命周期 | 作用 |
| --- | --- | --- | --- |
| **working** | `lastRunId`、`seenHashes`（内容指纹）、`openClusterKeys`、`notes` | 单会话/短周期 | 跨运行去重、避免同一批内容重复入库与重复告警 |
| **episodic** | 事件卡（≤40）：`eventId/title/clusterKey/riskLevel/decision` | 中期 | 为"历史先例"提供加成；记录人做过什么决定 |
| **semantic** | `sourcePriors`（Beta）、`keywordWeights`、`playbookRules`、`thresholds` | 长期 | 把人的判断沉淀成规则，改变下一次打分与排序 |

## 2. 源先验：为什么用 Beta 而不是"加减分"

每个源维护 `reliability = Beta(6·base, 6·(1−base))` 的后验均值：

- 初始 `base` 来自注册表的静态可信度（S=0.95 … D=0.35），等价于"先给 6 次虚拟样本"；
- 每次 `confirm` → `accepted+1`，`reject` → `rejected+1`；
- 后验均值 = `(α + accepted) / (α + β + accepted + rejected)`。

好处：**第一次误判不会把源打成 0**，需要持续、多次的相反证据才会显著移动。这正是内部工具需要的"慢变量"。

## 3. 反馈闭环（四动作）

| 动作 | 语义 | 对记忆的影响 |
| --- | --- | --- |
| `confirm` | 这条事件是真的、值得跟进 | 源先验 ↑；关键词权重 +0.12；事件卡 decision=confirm |
| `reject` | 误报 / 不成立 | 源先验 ↓；权重 −0.12；decision=reject |
| `promote` | 同类信号以后要更敏感 | 同 confirm，且标记为高优先主题 |
| `demote` | 同类信号以后少报 | 同 reject |

每次反馈写入 `FeedbackRecord{feedbackId,eventId,decision,reason,actor,at,scoreBefore}`——**保留决策前的分数**，这样半年后能回答"当时为什么给 82 分"。

## 4. 从反馈到规则（learned playbook）

同一事件被确认第 2 次时，自动生成：

> 「XX」同类信号已被人工确认 2 次，后续出现同主题事件默认进入产品评估。

当前 seed 规则 5 条（政策类优先回原文、资金类必须 3 源以上、舆情不得直接进排期、竞品功能只在有截图时计入、跨源冲突必须人工裁决）。规则在 `memory` 页面可见，`source` 字段区分 `seed` / `learned`。

## 5. 跨运行"已见"处理（一个真实踩坑）

最初实现：`seenHashes` 命中即当重复丢弃。结果第二次运行时**所有事件消失**（因为全部文档都"已见"），首页变成空白。

修正：已见文档标 `reused` —— 仍然参与聚合（事件继续存在），但计入 `newEvidence=0`，任务状态写"本期内容与历史重复，已复用旧证据（0 条新增）"。

这条修正的意义在于区分三件事：

- **没有新信号 ≠ 没有情报**：事件仍然存在，只是今天没有增量；
- **重复 ≠ 失败**：任务 `partial` 的语义是"零新增"，不是"跑挂了"；
- **幂等**：同一批语料跑 10 次，证据库不增长、事件不变、报告只多了运行记录。

## 6. 记忆的边界（不做的事）

- **不自动改阈值**：阈值是产品口径，只能人改。
- **不做向量召回**：当前 semantic 层是关键词权重，可解释优先；引入向量会带来"为什么这条被加权"的不可解释性。
- **不记忆隐私内容**：记忆里只存标题、主题词、源 ID，不存用户原话与个人信息。
- **不跨环境共享**：`localStorage`（`ttih:v2`），刷新保留、换设备不同步；生产环境应落库并带版本迁移。
