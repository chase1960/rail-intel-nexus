# 面试叙事 · PM-NARRATIVE

> 一句话版本：**我把一个"看起来很完整、其实全是假数据"的 AI 情报产品原型，改成了一条可审计的流水线——重点不是让它更漂亮，而是让它第一次能回答"你凭什么这么说"。**

---

## 1. 这个问题值不值得做（30 秒版）

火车票产品的判断高度依赖"外部信息 + 内部规则"的比对：政策一变，搜索、下单、支付、退改、客服五条链路同时受影响；竞品上一个"退票费预估"，可能明天就有用户问"你们为什么没有"；小红书一条"30 天预约"攻略，可能让客服一天接 200 个电话。

现状是**人肉盯 + 群转发 + 凭感觉排优先级**，三个典型失败：

1. 拿到信息但**不知道真假**（官方 30 天 vs 网传 60 天）；
2. 知道真假但**不知道排第几**（40 条线索里凭感觉挑 3 条）；
3. 排了序但**落不到动作**（结论停在"建议关注"）。

所以这个产品要解决的不是"信息不够"，而是**"信息不可信、不可比、不可执行"**。

---

## 2. 我做的四个关键决定（每个都带取舍）

### 决定 1：先把"假"清掉，再谈功能

- 原状态：首页指标硬编码、日期写死 2025-07-10、导出 PDF/Excel 是 `toast` 假成功、MCP 工具读的是写死的对象数组。
- 我的处理：删 `mock-data`、删假按钮、所有指标改为流水线现算、时间改为相对当前生成。
- **取舍**：短期看"没有原来那么多漂亮数字了"，但换来了"每个数字都能点开溯源"。内部工具的信任成本极高，一次假成功会让后面所有结论被怀疑。

### 决定 2：把"不能采信"做成一个状态，而不是丢掉

- 打分 5 维（权威/可核验/多源/时效/密度），冲突 −20，<55 直接 `blocked`。
- 冲突证据**保留在证据库**，事件标记 `human_review`，参考意见自动降为 `watch`。
- **取舍**：不做"一条结论一个分"，而是"每条证据一个分 + 每个事件一个置信度"。多一层结构，换来"报告里每句话都能追到一条原文"。

### 决定 3：产物不是"结论"，是"带证伪条件的参考意见"

每条高优先级事件必须给：立场（act/watch/hold）、依据（证据结构/时间跨度/产品落点/历史先例/反证）、**证伪条件**（什么情况下我错了）、**验证动作**（30 分钟内怎么核）、**使用边界**（能用于内部排序，不能做对外口径）。

- **取舍**：这比"给个结论"啰嗦得多，但它把 AI 的输出从"判断"降级为"可被反驳的假设"——这才是人在环的正确姿势。没有官方原文时，立场一律 `watch`。

### 决定 4：自进化只改权重，不改事实

- 三层记忆：working（去重指纹）/ episodic（事件卡与人工决策）/ semantic（源先验 Beta、关键词权重、playbook）。
- 一次反馈影响源先验、关键词权重，同一事件第 2 次确认才生成一条 learned 规则；每条反馈留 `scoreBefore` 审计。
- **取舍**：不做全自动学习。因为情报系统里"没有人确认的自动学习"等于"用错的东西训练自己"。

## 3. 一个我踩到并修掉的真实 bug（讲这个最能体现深度）

**第二次运行，首页全空了。**

原因：跨运行去重把"已见内容"直接当重复丢弃 → 第二次跑，所有文档都"已见"，证据为 0，事件为 0。

修法：区分「重复」与「已见」——已见文档标 `reused`，仍参与聚合（事件继续存在），但 `newEvidence=0`，任务状态写"本期内容与历史重复，已复用旧证据（0 条新增）"。

这件事让我明确了三个语义：**没有新信号 ≠ 没有情报；重复 ≠ 失败；幂等 ≠ 空白**。这三条现在写进了引擎不变量。

另一个：**事件类型与标题自相矛盾**。原实现"任一证据命中 policy 就判政策事件"，导致「去哪儿新增退票费预估」被标成政策变化。改成"按信息类别投票 + 代表证据取中选类别最高分"，标题、类型、立场三者对齐。

## 4. 怎么衡量它有没有用（不是 DAU）

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 情报→动作的转化率 | 5 个事件，4 个给到模块与动作 | 周维度 ≥ 30% 事件进入产品评估 |
| 误报率 | 靠人工 reject 统计 | < 20% |
| 首条 P1 的发现时延 | 相对时间语料，同一轮内 | 官方发布后 4 小时内 |
| 人工复核成本 | 每条事件 4 个验证动作 | 单条 < 15 分钟 |
| 证据可回溯率 | 100%（每条证据有 URL/快照字段） | 保持 100% |

其中我最看重**误报率**：情报系统的失败不是"漏一条"，而是"错一条还被拿去开会"。

## 5. 面试常问的 5 个问题（我的答法）

**Q1：为什么不用 LLM 直接读完全部原文给结论？**
A：可以用，但只能用在"抽取"环节（标题归一、实体识别），不能用在"判定冲突"环节。冲突判定必须可复现、可解释、可审计；LLM 判"这两条冲突"无法回答"凭什么"。现在的规则版误报代价是多一次人工确认，模型误判的代价是把谣言写进政策文档。

**Q2：数据都是样本，这个项目怎么证明有效？**
A：分两层。工程有效性：`npm run verify` 能复现阶段计数、5 个事件、报告 197 行、反馈后源先验 0.780→0.811、二次运行 0 新增——这条链路是真的在跑。业务有效性：目前没接真源，README 里明确写了"未接真实抓取"，下一步是 3 个真源 + URL 可达性校验。**我不会用一个没接真源的系统去宣称准确率。**

**Q3：为什么不做全自动推送？**
A：情报的价值在于"排序"，不在于"通知"。没有人工确认的自动推送会训练用户忽略通知（告警疲劳）。现在的设计是 P1 进人工队列，确认后才进报告与推送，且每条意见带证伪条件。

**Q4：这套东西和"RAG 问答"有什么本质区别？**
A：RAG 回答"文档里说了什么"，这套回答"这件事该不该做、先做哪个、什么情况下我错了"。前者是检索，后者是判断 + 排序 + 可反驳。所以它的产出是"带边界的建议"而不是"摘要"。

**Q5：如果只给你两周，你砍什么？**
A：砍掉全部页面，只留三样——源注册表 + 打分 + 日报 Markdown。因为**决策链路的价值 80% 在"证据可信 + 排序"**，界面是可替换的壳。这也是我把引擎做成纯函数、与 React 完全解耦的原因。

## 6. 如果入职，前 90 天

1. **0–30 天**：接 3 个真源（12306 公告、公众号、App Store 评论），把"证据可核验"从规则推断变成真的 URL 检查 + 快照。
2. **30–60 天**：接内部策略库/PRD（MCP 工具），产出"现有实现 vs 新规则"的差异清单，让参考意见能引用 PRD 条款。
3. **60–90 天**：跑通一次真实的"政策 → 产品动作 → 上线 → 效果回落"闭环，用误报率与转化率证明这条链路值得继续投入。
