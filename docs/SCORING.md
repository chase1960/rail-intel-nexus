# 打分与校验 · SCORING

引擎的打分不是"给个综合分"，而是**先回答"这条信息凭什么被信"**，再把答案拆成可复核的维度。

## 1. 五维加权（满分 100）

| 维度 | 权重 | 计算 | 为什么需要它 |
| --- | --- | --- | --- |
| 来源权威度 | 25 | S=25 / A=21 / B=15 / C=9 / D=4，官方源 +2 | 政策类事实必须回到官方 |
| 可核验性 | 20 | 有 URL +6，有明确日期 +5，有数字/条款 +5，有作者/机构 +4 | "听说过"和"能点开看"不是一回事 |
| 多源印证 | 20 | 同锚点独立来源数：1→8, 2→13, 3→17, ≥4→20 | 单一来源的高分是脆弱的 |
| 时效性 | 15 | 24h=15, 72h=11, 7d=7, 30d=3（指数衰减） | 政策征求意见稿有窗口期 |
| 信息密度 | 10 | 数字/日期/条款数量映射 | 空泛评论不该和公告同分 |

叠加项：**历史先例加成**（episodic 中同类事件 ≤ +8）、**冲突扣分**（−20）。

## 2. 分档与状态

| 总分 | grade | 处置 |
| --- | --- | --- |
| ≥ 75 | `pass` | 进入聚合，可作为事件主证据 |
| 55–74 | `warning` | 进入聚合，但需人工复核 |
| < 55 | `blocked` | 不进入聚合，保留在证据库解释"为什么没用" |

`verificationStatus` 8 态由分数 + 来源访问方式 + 冲突共同决定：

`verified_online`（官方且可达）/ `verified_snapshot`（有快照）/ `verifying`（高分待核实）/ `unverified`（低分）/ `lead_only`（仅线索）/ `conflict`（口径冲突）/ `blocked`（不可采信）/ `obsolete`（超窗口过期）。

## 3. 政策依据资格（`canBePolicyEvidence`）

同时满足才为 true：

1. `grade = pass`；
2. 无冲突；
3. 来源官方（`isOfficial`）；
4. 权威级 ≥ A（`authorityRank ≥ 4`）。

这条规则的意义：**"能写进内部文档"和"能拿去做对外口径"是两件事**。报告里凡是讨论"政策事实"的段落，只允许引用这四类证据；其余一律写"线索"。

## 4. 冲突判定（规则版）

```
对同一锚点簇内任意两条证据 (a, b)：
  权威级差 ≥ 2  且  (
      弱方文本命中冲突标记：未证实 / 不一致 / 与官方 / 辟谣 / 未在 / 存疑 / 未经确认
      或 双方的"天数"口径不一致（如 30 天 vs 60 天）
  )  → 双方标 conflict，事件 status=human_review，stance 降级 watch
```

不用 LLM 的原因：冲突判定必须**可解释、可复现、可审计**；用一个可解释的规则带来的误报，好过一个说不清理由的模型判断。规则误报的代价是"多一次人工确认"，模型误判的代价是"把谣言当政策"。

## 5. 分数如何影响下游

| 下游 | 用到的字段 |
| --- | --- |
| 事件置信度 | avg / max / 独立来源数 / 是否有官方 |
| 风险分级 | confidence + 政策类标记 + 资金风险信号 + 冲突 |
| 参考意见 | 代表证据分数、官方数、冲突数、历史先例 |
| 报告 | 证据清单按分排序，`canBePolicyEvidence` 单独标注 |
| MCP | `list_evidence` 返回全部分维度与 `scoreGrade` |

## 6. 阈值从哪来、怎么改

阈值集中在 `memory.semantic.thresholds`（`passScore=75`、`warningScore=55`、`clusterSimilarity=0.3`）。

**改阈值的正确姿势**：不要因为"某天觉得太严"直接改常量；先用 `scripts/verify-engine.ts` 跑同一批语料，比较 pass/warning/blocked 数量变化，再决定是否改。阈值是产品口径，不是个人手感。

## 7. 已知弱点

- 权威度是**静态映射**，没有按"该源历史上被推翻过几次"动态调（源先验目前只影响关键词权重与 playbook，尚未回灌打分）。
- 「多源印证」未扣"同一稿通发"（多家转载同一通稿会被当成多源）；正确做法是先在去重层识别通稿模板。
- 时效性对"长期有效规则"过于苛刻：一条 3 年前发布、但现在仍然有效的规则会被压分；需要引入"有效期"字段替代发布时间。
